全国の自治体が、デジタル庁の定める自治体標準オープンデータセット31項目を実際に公開しているかどうかを観測して公開するデータセット。

## データ出典

[自治体標準オープンデータセット（デジタル庁）](https://www.digital.go.jp/resources/open_data/municipal-standard-data-set-test)が31項目を定義している。1〜17と23〜31はデジタル庁が様式を公開し（データ項目定義書A〜D）、18は国土交通省の地質・土質調査成果電子納品要領、19は都市計画基礎調査、20は[デジタル社会推進実践ガイドブック DS-451-8 実装データモデル（行政）調達](https://github.com/JDA-DM/GIF/tree/main/451_%E5%AE%9F%E8%A3%85%E3%83%87%E3%83%BC%E3%82%BF%E3%83%A2%E3%83%87%E3%83%AB_%E8%A1%8C%E6%94%BF)、21は標準的なバス情報フォーマットが様式を定める。

公開状況は各自治体のオープンデータカタログの API を観測して求める。観測したカタログは `ods.portal` にある。データ本体は取得せず、件数と組織別の内訳だけを読む。

## スキーマ: ods（自治体標準オープンデータセット）

- ods.measurement: 団体 × 項目の公開状況
- ods.item: 31項目の定義と、判定に使った検索語
- ods.portal: 観測対象のカタログと、観測できたかどうか
- ods.search_word_hit: 検索語ごとのヒット数（判定根拠）

## テーブル: measurement

1行 = 団体 × 項目 × 観測。公開していない組み合わせも `is_published = false` の行として存在するので、「出していない」を数えるのに LEFT JOIN は要らない。

- lg_code: 全国地方公共団体コード（6桁、検査数字付き）
- lg_code_5: 検査数字を除いた5桁
- prefecture_code: 都道府県コード（先頭2桁）
- item_no: 項目番号（1〜31）
- item_key: 項目キー
- item_label: 項目名
- definition_book: データ項目定義書（A〜H）
- is_published: 観測時点で公開を確認できたか
- dataset_count: 一致したデータセット数
- portal_id: 観測したカタログ
- measured_on: 観測日

`lg_code` で dataset-lg-code、dataset-houjin-bangou、dataset-zipcode と結合できる。

## 判定の性質と限界

判定はデータセット名（タイトル）の部分一致による近似で、公式の公表値ではない。次の癖がある。

タイトルに項目名を含まないデータセットは拾えない。たとえば入札結果を「契約情報」というタイトルで公開している団体は、項目20（調達情報）の検索語に当たらない。実際の公開状況より少なく出る方向に偏る。

逆に、別の用途のデータセットが当たることがある。項目25（公営駐車場一覧）の検索語「駐車場」は、観光施設の付帯駐車場を含むデータセットにも一致する。

説明文は見ずタイトルだけを見る。これは意図的で、フリーテキスト検索にすると桁が変わるため。BODIK 横断カタログで「オープンデータ一覧」を全文検索すると10,553件（カタログ全体の半分以上）が当たるが、タイトル限定なら125件になる。

検索語は `ods.item` の `search_words` にあり、語ごとのヒット数は `ods.search_word_hit` で確認できる。ある項目の団体数が少ないとき、公開が少ないのか語が合っていないだけなのかを切り分けられる。

## 観測範囲

`ods.portal` に載っているカタログだけが観測対象で、そこに参加していない団体は `measurement` に行を持たない。行が無いことは「公開していない」ではなく「観測していない」を意味する。全国の団体を分母にした割合を出すときは、dataset-lg-code と突き合わせる。

個別自治体のサブサイト（`odcs.bodik.jp/<団体コード>/` など）は多くが CMS のフロントで API を持たないため、横断カタログ側から一括で観測している。

## データ更新手順

`main.py` が各カタログの CKAN API を叩いて `data/*.ndjson` を作り、dbt build でテーブルを再生成する。

CKAN（Solr）の癖が2つあり、これを外すと数字が桁で変わる。スペース区切りは AND として解釈され `OR` キーワードは効かないため、語ごとに個別のクエリを投げて団体の集合として和を取る。フリーテキストは説明文まで一致するため、タイトル限定で検索する。

リクエストは2秒以上の間隔を空け、User-Agent に連絡先を入れて送る。データ本体は取得しない（`rows=0`）。
